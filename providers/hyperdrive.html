HyperDrive

HyperDrive sits between the OASIS kernel and the provider layer. It handles replication, failover, health monitoring, and data migration across all registered providers.

How It Works

On every write, HyperDrive:

  1. Writes to the primary provider.
  2. Asynchronously replicates to all backup providers in the configured list.
  3. Tracks success/failure per provider and updates health scores.

On every read, HyperDrive:

  1. Attempts the primary provider.
  2. If it fails or is below the health threshold, falls over to the next backup provider.
  3. Returns the result from whichever provider first responds successfully.

Configuration

json — OASIS_DNA.json
{
  "OASIS": {
    "StorageProviders": {
      "AutoFailOverEnabled":                 true,
      "AutoReplicationEnabled":              true,
      "AutoLoadBalanceEnabled":              true,
      "AutoFailOverProviders":               "MongoDBOASIS, SQLLiteDBOASIS, Neo4jOASIS",
      "AutoReplicationProviders":            "MongoDBOASIS, SQLLiteDBOASIS, Neo4jOASIS",
      "AutoLoadBalanceProviders":            "MongoDBOASIS, SQLLiteDBOASIS, Neo4jOASIS",
      "AutoLoadBalanceReadPollIntervalMins":  10,
      "AutoLoadBalanceWritePollIntervalMins": 10
    }
  }
}

Provider Status and Metrics

HyperDrive tracks each provider's availability, latency and error rate. A provider that is down is skipped (fail-over) until it recovers. Read the live state at runtime:

GET/api/hyperdrive/status
GET/api/hyperdrive/metrics
GET/api/hyperdrive/metrics/{providerType}
GET/api/hyperdrive/dashboard
GET/api/hyperdrive/best-provider

Replication and Fail-over Rules

Writes go to the primary and are copied to every provider in AutoReplicationProviders through a per-holon outbox, so replicas catch up even after an outage. Inspect or change the rules and triggers with:

GET/api/hyperdrive/replication/rules
GET/api/hyperdrive/replication/triggers
GET/api/hyperdrive/failover/rules
GET/api/hyperdrive/failover/triggers

Quota and cost controls live under /api/hyperdrive/quota/* and /api/hyperdrive/costs/*. MongoDB must run as a replica set for HyperDrive's atomic writes.

Load Balancing

When AutoLoadBalanceEnabled is true, HyperDrive spreads reads across the providers in AutoLoadBalanceProviders with a round-robin, skipping any that are down. Suitable for read-heavy deployments with multiple fast providers.

⚠️
Eventual consistency

Async replication means backup providers may be briefly behind the primary after a write. For reads that must see the latest write immediately, either disable async replication (set synchronous mode) or always read from the primary by passing providerType explicitly.
