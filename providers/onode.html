ONODE Setup

An ONODE is a self-contained OASIS node running the WebAPI, managing providers, and optionally joining the ONET peer-to-peer network.

Prerequisites

  • .NET 10 SDK
  • At least one provider dependency (e.g. MongoDB, SQLite — no extra install needed for SQLite)
  • Redis (only required for multi-node ONET deployments with DID auth)

Local Development

terminal
cd NextGenSoftware.OASIS.API.ONODE.WebAPI
dotnet run
# API available at http://localhost:4000
# Swagger UI at  http://localhost:4000/swagger
⚠️
Always build before running

The OASIS provider interfaces cascade across 33+ projects. Run dotnet build in the solution root before starting the ONODE to catch interface mismatches early.

OASISDNA.json

All ONODE configuration lives in OASISDNA.json alongside the WebAPI project. Key sections:

json
{
  "OASISDNA": {
    "DefaultProviderType":    "MongoDBOASIS",
    "BackupProviderTypes":    [ "SQLiteOASIS" ],
    "AutoFailoverEnabled":    true,
    "AutoReplicationEnabled": true,
    "EnableDIDAuth":          false,
    "ONodeName":              "MyONode",
    "ONodeDescription":       "Community ONODE",
    "JWTSecret":              "<32+ char secret>",
    "MongoDBConnectionString": "mongodb://localhost:27017",
    "MongoDBDatabaseName":     "OASIS"
  }
}

Joining ONET

To join the decentralised ONET network your ONODE must:

  1. Have a publicly routable IP/hostname.
  2. Enable DID auth ("EnableDIDAuth": true).
  3. Use Redis nonce store ("NonceStoreType": "Redis").
  4. Register with the ONET bootstrap node (contact the OASIS team for the current bootstrap address).
ℹ️
ONET DID auth + in-memory nonce store

Using in-memory nonce store with DID auth on ONET will cause nonce validation failures across nodes. A startup warning is logged. Switch to Redis before joining ONET.

Docker

terminal
docker build -t onode .
docker run -p 4000:4000 \
  -v $(pwd)/OASISDNA.json:/app/OASISDNA.json \
  onode

Hosting an ONODE

ONODEs run on many kinds of host: Railway, Holo, ThreeFold, Akash, Flux, Fly.io or the Oracle free tier, Raspberry Pis and home servers. Each node should only start what its host supports.

Host profiles and connection modes (proposed, not built yet)

Do not add these keys to a live configuration: no code reads them yet.

  • ONODE.HostProfile: Name, CanRunSidecars, AllowedSidecars, MaxMemoryMB, Architecture (x64 or arm64).
  • Per provider, ConnectionMode: External (hosted, with ConnectionString), Local (same machine or private network, with LocalAddress), Sidecar (the node starts it) or Disabled.
  • A node activates a provider only if its mode works on that host. Unsupported providers are skipped with a clear log line, and HyperDrive uses only the providers the node really has.

Cheap provider hosting

  • Neo4j AuraDB Free; MongoDB Atlas Flex; SQLite and LocalFile on the node itself.
  • Upstash for Redis-like storage; IPFS gateways plus a free pinning tier.
  • Public or testnet RPC for blockchains; Holo for Holochain.
  • Peer-to-peer networks that suit a decentralised ONODE network: IPFS, Holochain, Nostr, ThreeFold, Ceramic and OrbitDB.

Free-tier limits change, so check them before relying on one.

On-demand sidecars (on the Development branch)

The helper processes behind the CQL sandbox sources can start only when a query needs them and stop when idle. Settings are under OASIS.Sandbox.Sidecars: OnDemand (default false), IdleMinutes (default 10, minimum 2) and AlwaysOn (comma-separated source providers). Log lines start with SIDECAR (start, ready, stop, crash, failure). Wizard avatars can read their state:

GET/api/admin/cql/sidecars
